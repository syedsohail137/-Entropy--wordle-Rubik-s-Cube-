# Entropy: Wordle × Rubik's Cube

A C++ research repository exploring entropy, probabilistic state transitions, symbolic market behavior, lossless compression, and visual toy experiments.

The repository currently contains three main areas:

1. **Brent crude oil prototype** — an experimental GARCH-inspired C++ pipeline that generates synthetic candle data, discretizes price behavior into symbolic tokens, and calculates transition frequencies and entropy.
2. **V9+ lossless compression benchmark** — an independent C++17/C++20 range-coding experiment that combines online context experts and language-aware prediction.
3. **Entropy toys** — visual and experimental prototypes exploring word/token sequences and Rubik-style structures.

> **Research notice:** The market and toy projects are prototypes for experimentation and education. The Brent pipeline is not a validated trading strategy and is not a source of investment advice.

## Features

- GARCH-inspired conditional volatility calculation
- Dynamic OHLC candle discretization
- Three-candle symbolic market motifs
- Shannon entropy-based filtering
- Bullish and bearish probability estimates
- 32-bit range coding and online compression experts
- Language-aware XML, MediaWiki, word, and phonotactic contexts
- CSV input and output support
- Exploratory visual assets and prototype source code

## Main C++ prototype

The executable in `main.cpp`:

1. Generates 200 rows of simulated OHLC-style data.
2. Creates `input_XBRUSD.csv` in the current working directory.
3. Parses open, high, low, and close values.
4. Computes GARCH-inspired volatility values.
5. Converts candle behavior into symbolic tokens.
6. Finds repeated three-candle motifs.
7. Writes predictions and entropy measurements to `output.csv`.

The included `output.csv` is generated sample output, not a record of real Brent trading activity.

### Build

Requires a C++ compiler with C++11 or newer support.

```bash
g++ -std=c++11 -O2 main.cpp -o entropy_market
```

### Run

From the repository root:

```bash
./entropy_market
```

This creates:

- `input_XBRUSD.csv` — generated synthetic input
- `output.csv` — computed output

### Output columns

`output.csv` contains:

| Column | Description |
|---|---|
| `Date` | Synthetic date |
| `Open` | Synthetic opening price |
| `High` | Synthetic high price |
| `Low` | Synthetic low price |
| `Close` | Synthetic closing price |
| `GARCH_Vol` | GARCH-inspired volatility estimate |
| `Token` | Dynamic symbolic candle token |
| `t_plus_1_Entropy` | Entropy of observed next-token transitions |
| `t_plus_1_PredictedToken` | Most frequent predicted token |
| `TradingSignal` | `EXECUTE_LONG`, `EXECUTE_SHORT`, or `HOLD_NEUTRAL` |
| `SignalConfidence` | Confidence percentage |

## V9+ 1.8956 compression benchmark

The [`1.8956/`](1.8956/) directory contains V9+, a cold-start lossless compression experiment targeting Hutter Prize-style English/Wikipedia data.

A recorded run of the included 750,000-byte `enwik9_750kb.txt` sample reported:

- **Compressed size:** 177,725 bytes including the length header
- **Model bpb:** 1.8956 bits per byte
- **Actual bpb:** 1.8957 bits per byte
- **Lossless verification:** exact source/decoded match
- **Gain over V8:** 0.2681 bpb

These values describe one observed benchmark run and may vary with compiler flags, CPU architecture, and input size.

### Build

From the `1.8956/` directory:

```bash
g++ -O3 -std=c++17 -march=native main.cpp cli.cpp -o v9_hutter
```

A portable build is also available:

```bash
g++ -O3 -std=c++17 main.cpp cli.cpp -o v9_hutter
```

### Run

```bash
cd 1.8956
./v9_hutter --file enwik9_750kb.txt
```

Additional usage is documented in [`1.8956/README.md`](1.8956/README.md).

## Methodology summary

### Brent prototype

The primary market prototype uses a simplified GARCH(1,1)-style variance recurrence:

```text
variance = omega + alpha × previous_return² + beta × previous_variance
volatility = square_root(variance)
```

It maps candles into symbolic tokens, searches for repeated three-token motifs, estimates transition probabilities, and calculates Shannon entropy:

```text
H = -Σ p(x) log₂(p(x))
```

Low entropy and sufficient bullish or bearish probability can produce a directional signal. These rules are heuristic and should not be interpreted as a statistically validated forecast.

### V9+ benchmark

V9+ uses a 32-bit range coder, 16 online prediction experts, a stretched-logit logistic mixer, adaptive probability maps, and language-aware parser state. It builds context from the input without external dictionaries or pretrained weights.

## Limitations

- `main.cpp` does not load real Brent market data; it creates simulated CSV data.
- The GARCH parameters and thresholds are embedded constants, not fitted estimates.
- The transition model does not use a train/test split or walk-forward validation.
- Historical token matching can suffer from sparse samples and data snooping.
- Compression benchmark results are specific to the supplied sample and build environment.
- Visual prototypes are not integrated with the market or compression pipelines.
- No automated test suite or benchmark harness currently covers every project component.

## Suggested next steps

- Accept real Brent CSV data through command-line arguments.
- Separate data loading, GARCH estimation, tokenization, entropy, and reporting into modules.
- Add CMake or Meson build configuration.
- Add unit tests for volatility, tokenization, entropy, and range-coding calculations.
- Fit GARCH parameters instead of using hard-coded values.
- Implement rolling train/test and walk-forward evaluation.
- Report accuracy, calibration, and transaction-cost-adjusted backtests.
- Expand reproducible compression benchmarks across multiple datasets and compiler configurations.
- Add a data provenance section for external datasets.
