# Entropy: Wordle × Rubik's Cube

A C++ research repository exploring entropy, probabilistic state transitions, symbolic market behavior, and visual toy experiments.

The repository currently contains two distinct areas:

1. **Brent crude oil prototype** — an experimental GARCH-inspired C++ pipeline that generates synthetic candle data, discretizes price behavior into symbolic tokens, and calculates transition frequencies and Shannon entropy.
2. **Entropy toys** — visual and experimental prototypes for exploring word/token sequences and Rubik-style structures.

> **Research notice:** This project is a prototype for experimentation and education. It is not a validated trading strategy or a source of investment advice.

## Features

- GARCH-inspired conditional volatility calculation
- Dynamic OHLC candle discretization
- Three-candle symbolic market motifs
- Shannon entropy-based filtering
- Bullish and bearish probability estimates
- CSV input and output support
- Exploratory visual assets and prototype source code

## Main C++ prototype

The main executable in `main.cpp`:

1. Generates 200 rows of simulated OHLC-style data.
2. Creates `input_XBRUSD.csv` in the current working directory.
3. Parses open, high, low, and close values.
4. Computes GARCH-inspired volatility values.
5. Converts candle behavior into symbolic tokens.
6. Finds repeated three-candle motifs.
7. Writes predictions and entropy measurements to `output.csv`.

The included `output.csv` is generated sample output, not a record of real Brent trading activity.

### Build

Requires a C++ compiler with C++11 or newer support.

```bash
g++ -std=c++11 -O2 main.cpp -o entropy_market
```

### Run

From the repository root:

```bash
./entropy_market
```

This creates:

- `input_XBRUSD.csv` — generated synthetic input
- `output.csv` — computed output

### Output columns

`output.csv` contains:

| Column | Description |
|---|---|
| `Date` | Synthetic date |
| `Open` | Synthetic opening price |
| `High` | Synthetic high price |
| `Low` | Synthetic low price |
| `Close` | Synthetic closing price |
| `GARCH_Vol` | GARCH-inspired volatility estimate |
| `Token` | Dynamic symbolic candle token |
| `t_plus_1_Entropy` | Entropy of observed next-token transitions |
| `t_plus_1_PredictedToken` | Most frequent predicted token |
| `TradingSignal` | `EXECUTE_LONG`, `EXECUTE_SHORT`, or `HOLD_NEUTRAL` |
| `SignalConfidence` | Confidence percentage |

cd hutter-v17-2.38
make

Run the resulting executable according to the program's command-line behavior in `main.cpp`. The project has not been integrated into the main Brent pipeline.

Clean the build output with:

## Methodology summary

The primary prototype uses a simplified GARCH(1,1)-style variance recurrence:

```text
variance = omega + alpha × previous_return² + beta × previous_variance
volatility = square_root(variance)
```

It then maps candles into symbolic tokens, searches for repeated three-token motifs, estimates transition probabilities, and calculates Shannon entropy:

```text
H = -Σ p(x) log₂(p(x))
```

Low entropy and sufficient bullish or bearish probability can produce a directional signal. These rules are heuristic and should not be interpreted as a statistically validated forecast.

## Limitations

- `main.cpp` does not load real Brent market data; it creates simulated CSV data.
- The GARCH parameters and thresholds are embedded constants, not fitted estimates.
- The transition model does not use a train/test split or walk-forward validation.
- Historical token matching can suffer from sparse samples and data snooping.
- Visual prototypes are not integrated with the market pipeline.
- No automated test suite or benchmark currently exists.

## Suggested next steps

- Accept real Brent CSV data through command-line arguments.
- Separate data loading, GARCH estimation, tokenization, entropy, and reporting into modules.
- Add CMake or Meson build configuration.
- Add unit tests for volatility, tokenization, and entropy calculations.
- Fit GARCH parameters instead of using hard-coded values.
- Implement rolling train/test and walk-forward evaluation.
- Report accuracy, calibration, and transaction-cost-adjusted backtests.
- Add a data provenance and license section for external datasets.
